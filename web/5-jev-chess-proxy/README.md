# 5-jev-chess-proxy

> **Note:** This README was auto-generated by AI as a project summary.

## What it does

Server-side deployment of the Jev Chess app (see `games/5-jev-chess`) for
`jev-chess.tgr.rs`. A tiny Python proxy holds the TypeSafe API key so the
browser never needs one (no CORS origin allowlist required). The page calls
same-origin `/v1/systemone`; Caddy reverse-proxies that path to the proxy.

## Components
- `proxy.py` — stdlib-only Python 3.12-alpine service
  - injects the key (`TYPESAFE_API_KEY` env) as `Authorization: Bearer`
  - validates bodies as chess (permissive: `questions.move` choice with
    LAN keys + chess FEN; non-chess bodies → 400, so the endpoint is not a
    free TypeSafe API)
  - per-IP limits: 1 req/s, 1000/hour, 5000/day (sliding windows, in-memory)
- `index.html` — the chess page, wired to the same-origin endpoint
- `Caddyfile` — HTTPS (HTTP-01), static page, `/v1/systemone` → proxy with
  `X-Real-IP {remote_host}`
- `docker-compose.yml` — `proxy` + `caddy` on a private network
  (proxy has **no published port**)

## Spoof-proof client IP
The proxy is reachable only from the Caddy network (`172.30.42.0/24`,
`GATEWAY_SUBNET`). It trusts `X-Real-IP` **only** when the TCP peer is in that
subnet — Caddy sets the header from `{remote_host}` and overwrites any
client-supplied value, and a direct client cannot reach the proxy port at
all. Everyone else is limited by raw TCP peer IP.

## Deploy (on jev-chess.tgr.rs)
```
cp .env.example .env   # fill in TYPESAFE_API_KEY + CADDY_EMAIL
docker compose up -d --build
```
Needs DNS `jev-chess.tgr.rs → this box` with ports 80/443 open for the
Let's Encrypt HTTP-01 challenge.
